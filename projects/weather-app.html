Weather App

A real-time weather application focused on clean UI, clarity, and smooth user experience.

Role: UI/UX + Frontend Vanilla JS · API · UX

Goal

Build a weather app with real error handling and two ways to get a forecast — manual city search or auto-detected location — with a background that visually shifts to match the current conditions.

Development

  • Built in vanilla JavaScript using the Fetch API with async/await. Two entry points — manual search and navigator.geolocation on page load — both feed the same rendering function, so the UI stays consistent regardless of how the location was determined.
  • Every API call is wrapped in try/catch, with a loading state shown while the request is in flight and a clear error message on failure (bad city name, denied location permission).
  • The background gradient updates based on the returned weather condition, so the page itself communicates the forecast at a glance.

UI Screens

Challenges & Solutions

  • Handling failure gracefully — a misspelled city or a denied location request needed a clear failure path instead of a broken, silent UI.
  • The OpenWeatherMap API key was originally hardcoded in the JavaScript file and pushed to a public repo — moved into a local, gitignored config file, with the real key injected at deploy time from an environment variable so it never touches the repository.

Tech Stack & Links

HTML5 · CSS3 · Vanilla JavaScript · Tailwind CSS · OpenWeatherMap API
